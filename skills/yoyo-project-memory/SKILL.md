# Project Memory（项目记忆同步）

两层存储 + 口令驱动的记忆方案，git 即同步通道。适用于多机开发、长周期项目的上下文交接。

## 存储结构（项目内）

```
<repo>/
├── AGENTS.md            # §工作流：一行指针「本项目启用 yoyo-project-memory，口令见 skill」
├── docs/（或 doc/）
│   ├── 项目记忆.md      # 主快照（周级稳定事实）：里程碑 / 环境 / 红线 / 自测命令
│   └── 记忆增量/
│       ├── README.md    # 机制细则 + 增量文件模板
│       └── YYYY-MM-DD.md # 按日增量（会话级变化事实，≤50 行）
```

**目录选择**：默认放 `docs/`；若仓库已有 `doc/` 目录，则沿用 `doc/`（选定的目录以下称 `<记忆目录>`，同一仓库内固定不变）。

- **主快照**：低频刷新（合并时）。只放稳定事实，不放会话细节。
- **增量文件**：每次「记忆:保存」追加。四字段：`改动 / 决策 / 遗留 / 踩坑`，只写**增量事实**，不抄 AGENTS.md 与主快照已有内容。同一天多次会话追加同一文件。

## 口令（照做不发挥）

| 口令 | 行为 |
|---|---|
| `提交推送` | 纯 git：整理 Conventional Commits + `git push`，不动记忆文件 |
| `提交推送+记忆` | git 操作 + 把本次会话关键记忆追加到当天增量文件，**一次提交**推送 |
| `记忆:保存` | 只写/追加当天增量文件，不碰 git |
| `记忆:合并` | 全量合并：把 ≥5 天的增量提炼进主快照（刷新其 Updated），删除已合并增量文件 |
| `记忆:恢复` | 手动恢复；默认**增量**（补读比上次恢复新的增量），`记忆:恢复 全量` 按日期升序读完全部增量 |

## 自动恢复（会话开始 / `git pull` 后）

1. 读 `AGENTS.md` → 读主快照 `<记忆目录>/项目记忆.md`（`docs/` 优先，已有 `doc/` 则用 `doc/`）
2. 若本机/本会话**首次**恢复 → 读全部增量（全量）；否则只读日期**晚于上次已恢复到的增量文件**的（增量）
3. 发现主快照与增量矛盾 → 以增量（新）为准，不擅自改主快照（等「记忆:合并」）

## Bootstrap（给新仓库启用，一条指令完成）

用户说「给这个项目启用 yoyo-project-memory」时：
0. 定 `<记忆目录>`：默认 `docs/`；若仓库已有 `doc/` 目录则沿用 `doc/`（两者都无则建 `docs/`）
1. 建 `<记忆目录>/项目记忆.md`（骨架：项目快照 / 里程碑 / 环境与红线 / 自测命令，内容问用户或从 README/git log 提炼）
2. 建 `<记忆目录>/记忆增量/README.md`（复制本 skill 的模板段）
3. 在项目 `AGENTS.md` 工作流章节加一行指针（不复制全文）：
   `记忆同步：本项目启用 yoyo-project-memory skill（记忆目录：docs/，口令「记忆:保存/合并/恢复」「提交推送+记忆」，自动恢复见 skill）`（`docdir` 按目录选择规则实际填写）
4. commit+push 首份主快照

## 模板（增量文件）

```markdown
# 记忆增量 YYYY-MM-DD

- 改动：<file>：<一句话>（原因/对应需求章节）
- 决策：<拍板内容及理由>
- 遗留：<TODO>
- 踩坑：<一句话>
```

## 边界

- 增量写入一律**按口令批量补写**（会话要点攒着一次性写），不逐条实时追加打断代码工作
- 增量文件单份 ≤50 行；超限说明该写进主快照了，提示「记忆:合并」
- 记忆文件不进任何 CI/构建；不提交密钥/环境变量值（同 `.env` 红线）
- 已合并的增量只删工作区文件，git 历史即归档

## 环境要求

- 无系统依赖（纯 markdown 约定 + git），macOS / Windows / Linux 通吃
- 前提：项目是 git 仓库，且各机都能 pull/push（同步走 git 分发）
